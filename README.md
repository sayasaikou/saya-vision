# saya-vision

一套**用算法兜底、不信任模型自述**的看图工具链。

适用于任何"需要模型看清图"的场景：客服机器人、内容审核辅助、素材整理、
文档/截图理解、插画鉴定。**不依赖特定平台**。

---

## 为什么需要它：三个能复现的失败

市面上"把图丢给视觉模型问一句"的做法有三个稳定的失败模式，都是实测出来的。

### 1. 模型会把颜色看错

给模型看一件衬衫问颜色，**两个不同的视觉模型异口同声说是金色**。
用 PIL 取色一算：**深蓝近黑 `#272948`，占 62%**。

⇒ **颜色不该问模型**。它能算。

### 2. 整图提问会让模型"编"细节

一张 2560×1578（4 MP）的游戏插画，整图问"这图里是什么"：

> 回答：「金色长发，兜帽上有红色狐狸耳，**银色配红色的露脐装**……」

实际是：**红色无袖披风**（敞开）＋ 里面**银灰色胸衣**，**根本没有露脐**。

原因：4 MP 的图被缩到模型输入尺寸后，红披风和银灰胸衣**重叠成一个色块**，
模型就把两件的特征合并了。

**同一张图裁出上半身、放大 3 倍之后再问**：

> 「最外层是红色的兜帽/披风，无袖、敞开；里面一层是**银灰色、金属质感、带叶片状花纹的胸衣**；这块区域没有露出腹部皮肤。」

⇒ **看细节必须先裁出放大**。

### 3. 让模型"报坐标"很不可靠

试过在图上画坐标网格让模型读 `x1,y1,x2,y2`：一张 5000×5000 的图上它把**左上角的叶子**
报成了人物主体；换了张图它干脆**读不出坐标、没输出**。

⇒ 改成**画 4×4 带编号的格子（A1…D4），让模型说"人在哪几格"** —— 离散标签比读数字稳得多。

## 五个设计原则

| 原则 | 具体做法 | 验证 |
| --- | --- | --- |
| **能算的绝不问模型** | 尺寸、主色、区域配色一律用 PIL 算 | 模型集体看错颜色时，取色是对的 |
| **看细节先裁出放大** | 定位主体 → 裁剪 → 放大，再对**那一块**提问 | 同一张图，整图问错、裁块问对 |
| **分级增强，只做感知锐化** | 按块的清晰度自动定档；只在块**小**的时候上 AI 超分 | 小块 280×200：Lanczos 到 1596 方差 **93.5**，Real-ESRGAN 到 1120 就有 **1735.3**（18.6 倍）；大块（2545×1430）超分反而产出 38.8 MB 无法使用的巨图 ⇒ **大块不超分** |
| **定位用离散标签** | 格子编号代替像素坐标 | 读坐标两次失败；选格子稳定成功 |
| **结论要能指认** | 说"这是 AI 图"必须给出可在图上指出的证据（乱码文字 / 无连接点的部件 / 对称结构不一致） | — |

## 反向搜图：按图类型分派

**没有反向搜图时，文字搜索对"识别角色"几乎无效** —— 实测拿图上的水印原字去搜，
返回的是同名的音乐人和 1990 年代游戏 PDF。

| 图类型 | 服务 | 能给出 |
| --- | --- | --- |
| **动画截图** | [`trace.moe`](https://trace.moe) | 作品名 + 集数 + 出现时间 + 相似度 |
| 插画 / 同人图 | SauceNAO / ascii2d | 画师、作品、来源 |
| **AI 原创图** | —— | **任何工具都认不出**（它不存在于任何作品里，这时"认不出"是正确答案） |

`tools/trace-moe.py` 已实现，**无需 API key**。

注意： **必须带底气等级**：`trace.moe` 对**不是动画截图**的图会给一个 0.6~0.8 的"最接近"结果
（实测一张 AI 原创插画拿到了 0.615 的《命运石之门》）。判据：

```
≥ 0.90       可以当"就是这部"说
0.85 ~ 0.90  只能说"看着像"
< 0.85       不要说
```

## 工具

| 文件 | 作用 | 依赖 |
| --- | --- | --- |
| `tools/imgtool.py` | **算法层**：尺寸 / 主色 / 区域取色 / 裁图放大 / 格子定位 / 分级锐化 / 密度定位 | Python 3 + Pillow |
| `tools/trace-moe.py` | **反向搜图**（动画截图） | 仅标准库 |
| `tools/vrecheck.py` | 定位 → 裁图放大 → 重问 ＋ 取色 | Pillow + 视觉 API |
| `tools/eyeprobe.py` | 多模型并排 + 分块 + 自动仲裁（一致/冲突/孤证） | 多个视觉 API key |
| `workflows/vision-workflow.md` | 四步看图工作流（给**模型**读的作业指导） | — |
| `docs/使用判据.md` | 判据与实测记录 | — |

### 快速开始

```bash
pip install Pillow

# 先量尺寸（大图必须裁）
python tools/imgtool.py size photo.jpg

# 取色（颜色问题问它，不要问模型）
python tools/imgtool.py color photo.jpg --top 6
python tools/imgtool.py color photo.jpg --region 1100,300,1500,900 --top 5

# 裁出目标区域并放大（看细节必备）
python tools/imgtool.py crop photo.jpg --region 800,120,2480,1688 --out subj.jpg --scale 2

# 生成带格子编号的向导图（给模型选格子用）
python tools/imgtool.py locate photo.jpg --out guide.jpg --grid 4

# 分级锐化（按清晰度自动定档）
python tools/imgtool.py enhance subj.jpg --out subj_enh.jpg

# 反向搜图（动画截图）
python tools/trace-moe.py screenshot.jpg
```

## 已知边界

- **AI 超分只在小块上有意义**：大块（本来就清楚）超分要么变糊、要么产出几十 MB 的巨图。
  阈值写在 `imgtool.py` 的注释里，可按需调整。
- **超分会补出原图没有的细节**。用视觉模型对比超分前后的同一区域，它明确指出
  超分"补"出了原图没有的**描边和褶皱线** ⇒ **颜色判断一律在超分之前做**
  （`imgtool.py` 的取色独立于增强步骤，就是为了这个）。
- **`vrecheck.py` / `eyeprobe.py` 是为特定环境写的**：它们依赖几个具体的视觉 API
  （百炼 / 智谱等），参数化不完整。当成参考实现读，不要指望开箱即用。
- **正向识别能力受限于反向搜图的可达性**。如果部署环境无法访问 SauceNAO 等，
  插画类识别会明显变弱 —— 这是服务可达性问题，不是工具问题。
